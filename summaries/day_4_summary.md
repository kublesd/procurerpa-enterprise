# Day 4 — 采购数据隔离

## 做了什么

- 采购任务按组织、部门和采购品类隔离。普通采购员只能看到自己部门且自己品类的任务；管理员只能看本组织。
- 用户每次请求都从数据库读取真实权限，不相信 JWT 里伪造的组织、角色或品类范围。
- 创建开发测试任务时必须选择部门和品类，任务创建后会保存这些归属信息，并出现在采购任务列表和详情中。
- 普通采购员不能借用系统原有任务接口绕过采购权限。
- 演示数据包含采购管理员、IT 采购员、服务采购员、审批人和查看人，以及各自的部门和品类授权。
- 修复了当前 bcrypt 版本与 Passlib 不兼容导致的演示采购员无法登录问题。

## 实际环境验证

- Docker 本地服务、PostgreSQL、Redis、MinIO、后端和前端均已启动；后端健康检查通过，Chromium 已安装。
- IT 采购员能从登录页登录并进入系统；页面没有显示登录失败。
- IT 采购员创建了一条仅访问 `https://example.com/` 的测试任务。Skyvern 已启动 Chromium 并成功抓取页面内容。
- 该任务在 IT 采购员列表和详情中可见；服务采购员列表为空、直接访问详情返回 404；采购管理员可以看到本组织的任务。

## 验证结果

- 最小相关单元测试：`37 passed`。
- 真实浏览器任务没有完成点击动作，因为本地 `.env` 尚未配置 LLM。浏览器、任务创建和数据隔离均已实际运行，缺少的只有让代理决定下一步操作的 LLM 配置。

## 后续

配置一个可用的 LLM 后，使用同一条 IT 采购员测试任务即可完成“打开页面并点击链接”的完整浏览器自动化验收。
