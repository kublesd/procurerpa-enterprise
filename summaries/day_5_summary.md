# Day 5 — 采购风险识别

## 做了什么

- 采购任务提交前会先做风险检查，覆盖采购金额、供应商、供应商资质、报价偏离和操作类型 5 类情况。
- 金额达到 5 万、10 万和 100 万时，风险会逐级提高；选中报价比平均报价偏离 20% 或 50% 时，也会提高风险等级。
- 新供应商、资质无效、单一来源采购、预付款和供应商银行账户变更等情况会被明确标记，并给出能让业务人员看懂的原因。
- 金额为负数、平均报价为零、税率超出正常范围或操作类型不支持时，系统会直接拒绝，不让错误数据进入后续流程。
- 同时命中多条规则时，以最高风险为准。缺少供应商、资质或可比报价时，不会直接判为低风险，而是提示需要补充资料。
- 可以选择让 LLM 根据已经脱敏的采购说明补充判断。金额、供应商 ID 和报价不会发给 LLM，而且 LLM 不能把规则已经判出的风险调低。
- 风险等级、原因和命中的规则会保存在采购任务中，并出现在采购任务列表和详情里；原有的组织、部门和品类隔离继续生效。

## 实际环境验证

- 当前项目还没有独立的采购申请表和采购申请接口，现有采购写入入口只有开发测试任务接口。因此本阶段直接把风险检查接入这条真实的 Skyvern Task 创建链，没有再建一套采购任务流程。
- 测试中提交了一条金额为 10 万元的采购任务，系统在创建任务前将其判为 high，并把风险等级和判断依据写入任务扩展数据。
- 已验证正常采购、金额边界、新供应商、资质缺失或失效、报价偏离、特殊采购操作和缺少资料等场景。
- 已验证 LLM 返回错误内容、调用超时或试图降低风险时，系统仍保留原来的确定性判断。
- 本次没有连接真实 PostgreSQL 执行迁移，也没有调用真实 LLM 或运行浏览器任务；数据库写入和提交调用链通过测试替身验证，迁移通过离线 SQL 检查。
